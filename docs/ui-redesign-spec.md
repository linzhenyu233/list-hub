# 多平台商品发布中台 · UI 重设计方案（GEM Ops）

> 适用范围：现有前端运营台（Vue 3 + Element Plus，`frontend/`）。
> 设计目标：**与现有功能保持一致**、**风格统一**、**现代克制**、**可落地**。
> 当前已落地部分：设计 token（`frontend/src/styles/design-tokens.css`）+ 应用壳重 skin + 分组导航 + 业务页细节打磨（见第 5 节）。

---

## 0. 设计目标与原则

| 原则 | 含义 | 在系统里的体现 |
|---|---|---|
| 效率优先 | 运营高频操作（上下架、发品、批量发布）路径最短 | 列表行内操作、批量发布四步向导、筛选前置 |
| 克制用色 | 主色只代表"操作/选中"，平台色只代表"平台身份" | indigo 作品牌主色；微信绿 / 小红书红仅作标识 |
| 层级清晰 | 一屏只突出一件事 | 页面标题 → 统计 → 筛选 → 表格，分区明确 |
| 状态可见 | 每一次异步操作都有明确反馈 | 加载态、成功/失败 toast、离线告警、步骤进度 |
| 容错友好 | 危险操作二次确认、失败可重试 | 删除二次确认、批量失败清单可逐条重发 |

## 1. 视觉风格与整体设计语言

### 1.1 配色（Color）

设计语言代号 **GEM Ops**：以靛蓝（indigo）为品牌主色，沉稳专业，既不抢微信绿也不抢小红书红，三者共存时层级分明。

| 类别 | Token | 值 | 用途 |
|---|---|---|---|
| 品牌主色 | `--gem-brand` | `#4F46E5` | 主按钮、选中态、链接、焦点环 |
| 主色（深） | `--gem-brand-strong` | `#3F38B7` | 主按钮 hover/active、强调文字 |
| 主色（浅底） | `--gem-brand-soft` | `#EEF0FE` | 选中背景、图标底、信息提示 |
| 微信平台 | `--gem-wechat` | `#07C160` | 微信标识、微信状态标签 |
| 小红书平台 | `--gem-xhs` | `#FF2442` | 小红书标识、小红书状态标签 |
| 成功 | `--gem-success` | `#16A34A` | 销售中 / 正常 / 上架成功 |
| 警告 | `--gem-warning` | `#D97706` | 快到期 / 缺图 / 待处理 |
| 危险 | `--gem-danger` | `#DC2626` | 删除 / 异常 / 失败 |
| 页面底 | `--gem-bg` | `#F6F7F9` | 全局背景 |
| 卡片面 | `--gem-surface` | `#FFFFFF` | 面板、抽屉、弹窗 |
| 浅底面 | `--gem-surface-2` | `#FAFBFC` | 表头、输入框底 |
| 边框 | `--gem-border` | `#E6E8EB` | 卡片、分割线 |
| 主文本 | `--gem-text` | `#1F2733` | 标题、重要信息 |
| 次文本 | `--gem-text-2/3/4` | `#3D4654 / #667085 / #98A2B3` | 正文 / 辅助 / 占位 |

规则：
- **一个页面只有一个主色**：操作按钮用 indigo；微信/小红书相关仅用平台色做"标识"（标签、小圆点），不用于大面积填充，避免和"可点击主操作"混淆。
- 语义色严格对应状态（绿=好、黄=注意、红=坏），不在装饰中乱用。
- 深色侧栏（渐变 `#131C2E → #0F1729`）提供稳定"操作后台"心智，与白色内容区形成明确层级。

### 1.2 字体（Typography）

- 字体栈：`"PingFang SC", "Microsoft YaHei", system-ui, ...`（已在 `--gem-font`）。
- 字号阶梯（仅 8 级，避免任意值）：12 / 13 / 14 / 16 / 18 / 20 / 24 / 28。
- 字重：正文 400、强调 500、标题 600/700。
- 标题统一左对齐、`letter-spacing` 微收（-0.2px），显现代感。
- 数字 / 编码 / JSON 用等宽字体（`--gem-font-mono`），便于运营核对商品 ID、SKU 编码。

### 1.3 图标（Icon）

- 统一使用 Element Plus 图标库（`@element-plus/icons-vue`），线宽一致、尺寸分级（17px 导航 / 18–22px 统计 / 32px 空态）。
- 侧栏图标 17px，导航项与图标间距固定 10px。
- 图标只传达"类别"，不承载状态；状态交给标签（tag）文字表达，避免"图标+颜色"双重猜谜。
- 品牌标识用渐变方块 + 单一图标，不用花哨插画。

### 1.4 间距规则（Spacing，4px 栅格）

统一间距 token（`--gem-space-*`）：4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48。
- 组件内字段间距 16；区块之间 24；页面边距 28；统计卡 gap 14。
- 表单两列网格 `form-grid-2` 列间距 20。
- 所有 padding/margin 只允许取 token 值，禁止出现 7px、13px 这类"随手值"。

### 1.5 圆角 / 阴影 / 层级（Radius & Elevation）

- 圆角：控件 8px（`--gem-radius-sm`）、卡片 12px（`--gem-radius-md`）、大浮层 16px、胶囊 999px。
- 阴影三级（`--gem-shadow-sm/md/lg`）：卡片用 sm，悬浮/抽屉用 md，模态/图片预览用 lg。
- 阴影只用于"浮起"语义（抽屉、弹窗、悬浮工具条），静态面板用 1px 边框即可，不滥用阴影。
- 焦点态统一 `--gem-shadow-focus`（indigo 3px 环），键盘可达。

### 1.6 动效（Motion）

- 统一缓动 `cubic-bezier(.4,0,.2,1)`，时长 180ms。
- 仅对"状态变化"做微动效（hover 底色、抽屉滑入、tab 下划线、toast 出现）；列表/表格不做入场动画，保证大数据量下的流畅。
- 异步加载用骨架/行内 spinner，不整页转圈。

## 2. UI 层级逻辑（信息架构）

### 2.1 页面层级图

```
运营中心（顶栏：店铺切换 + 操作人 + 刷新 + 服务状态）
├── 微信小店 ──────────┬─ 微信商品（列表/详情/编辑/上架下架）
│                     └─ 发布微信商品（草稿 → 列表提交审核）
├── 小红书 ───────────┬─ 小红书商品（列表/详情/编辑/SKU 上下架）
│                     └─ 发布小红书商品
└── 批量与配置 ───────┬─ 批量发布商品（向导：导入→校验→映射→发布）
                      ├─ 类目映射（内部类目↔平台类目）
                      ├─ 店铺管理（各店可用性/授权巡检）
                      └─ 接口设置（微信/小红书授权与连接状态）
```

### 2.2 导航结构

- **侧栏（桌面）**：按上面三层分组（`el-menu-item-group`），当前页左侧 3px indigo 强调条 + 浅 indigo 渐变底。
- **顶栏**：左侧面包屑（运营中心 / 当前页），右侧固定四个高频控件：店铺选择、操作人、刷新、服务状态点。
- **移动端（≤620px）**：隐藏侧栏，底部 4 Tab 高频导航（微信 / 小红书 / 批量 / 更多），低频页收进"更多"抽屉——**现有逻辑已具备，样式随 token 同步更新**。

### 2.3 模块划分与信息架构

| 模块 | 页面 | 核心信息架构 |
|---|---|---|
| 商品运营 | 微信商品、小红书商品 | 列表为主：统计卡 → 搜索/筛选 → 表格 → 行内操作 → 详情/编辑抽屉 |
| 商品创建 | 发布微信/小红书商品 | 分区表单：基础信息(01) → 素材(02) → 属性(03) → 规格/SKU(04) → 履约(05) |
| 批量中枢 | 批量发布商品 | 四步向导：导入文件 → 校验与编辑 → 平台映射 → 确认发布 |
| 配置 | 类目映射、店铺管理、接口设置 | 巡检/维护型：状态一览 → 增删改导入 |

### 2.4 平台隔离心智模型

- "店铺"是隔离根：切店即清空旧店数据、自动对齐平台视图（微信店→微信商品，小红书店→小红书商品）。
- 顶栏店铺下拉项用平台色标签（微信绿 / 小红书红）一眼区分；当前店铺决定批量发布、类目映射、图片缓存的数据边界。

## 3. 操作逻辑（交互流程 / 状态反馈 / 效率）

### 3.1 全局状态反馈规范

| 状态 | 视觉规范 | 现有实现 |
|---|---|---|
| 加载中 | 行内 spinner / 骨架，不整页遮罩 | `v-loading` 已用，保留 |
| 成功 | 右上角绿色 toast + 操作项短暂禁用态 | `ElMessage.success` |
| 失败 | 红色 toast，带平台原文（便于运营判断原因） | 已做（如小红书上架失败显示平台原因） |
| 离线 | 顶部黄色告警条 + 侧栏红点 | `offline-alert` + `service-dot` |
| 空 | 插画/图标空态 + 一句人话 | `el-empty` |
| 危险操作 | 二次确认（删除/批量发布） | `ElMessageBox.confirm` |

新增建议：
- **异步操作统一"提交中"按钮态**：主操作按钮显示 loading 且文案变"提交中…"，禁止重复点击（现有 `actionId` 机制已部分覆盖，扩大至所有写操作）。
- **批量发布失败清单可见**：被平台拒的商品在"确认发布"步骤以红色行列出原因，支持在审核抽屉里改标题后重试（呼应货盘标题重名问题，见内存备注，属运营待办，设计时保证失败可定位可重试）。

### 3.2 操作路径与效率优化（按页面）

- **微信/小红书商品列表**：
  - 搜索栏（编码/关键词/价格/库存）前置，支持高级展开；状态分段/标签页一键切换。
  - 行内"详情 / 编辑 / 上架下架 / 删除"常驻，避免进详情才能操作。
  - 微信游标翻页只给上/下一页并提示"不支持跳页"，避免误导。
- **发布微信/小红书商品**：
  - 分区表单带步骤序号(01–05)与"本区说明"，长表单可定位。
  - 类目搜索→选叶子类目→自动带出属性/规格，减少空表单。
  - 规格维度像后台那样"可增删 + 配图"，SKU 表按规格组合自动生成，改值不丢价格库存。
  - 校验集中在提交时一次性提示（标题/编码/主图≥3/SKU 价格），不逐字段打断。
- **批量发布向导**：四步进度条常显；每步可独立返回；步骤间数据保留（批次/图片/映射），不重复导入。
- **店铺管理**：默认只显"店名 + 平台状态"，异常才出现"检查/续期"按钮，正常时无按钮可点，降低误操作。

### 3.3 关键流程重设计（草图）

批量发布向导（四步，`el-steps` 已落地，规范其文案与可达性）：
1. **导入文件**：拖拽/选择 Excel + 可选服务器货盘表；校验后进入下一步。
2. **校验与编辑**：批次概览（可发布 / 错误 / 缺主图 / 缺规格图）+ 图片匹配结果 + 分页编辑。
3. **平台映射**：类目按商品自动命中（类目映射表），品牌/运费/物流读店铺设置；缺失项红字提醒且拦截发布。
4. **确认发布**：发布进度可见，失败清单可逐条重试。

### 5.2 Token 与 Element Plus 映射（关键）

设计 token 通过覆盖 Element Plus 的 `--el-*` CSS 变量一次性作用到所有组件：
- `--gem-brand` → `--el-color-primary` 及其 light/dark 派生；
- `--gem-bg/surface/border/text-*` → `--el-bg-color*/--el-border-color*/--el-text-color*`；
- `--gem-radius-sm` → `--el-border-radius-base`；
- 因此**不改任何 `.vue` 逻辑**即可让按钮/表格/表单/标签/弹窗整体换肤。

### 5.3 实施顺序建议

1. ✅ 设计语言 token + 应用壳 + 分组导航（启动 `npm run dev` 即可见）。
