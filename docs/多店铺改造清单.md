### 1.2 新增 `shop_registry.py`（项目根，共享模块）

职责：

| 函数 | 说明 |
| --- | --- |
| `load_and_validate()` | 读 `shops.json`、校验必填字段、校验 `shop_id` 唯一、校验每平台 `is_default` 唯一；不合法则启动即报错（fail fast） |

## 2. 微信服务 `wechat/`

### 2.1 全局单例 → 客户端池

| 位置 | 现状 | 改造 |
| --- | --- | --- |
| `wechat/fastapi_server.py:77` | `store = WxStore(APPID, SECRET)` 模块级单例 | 改为 `_store_pool: dict[str, WxStore]` + `_store_lock` + `get_store(shop_id)`（懒加载，首次请求创建该店实例） |
| `wechat/fastapi_server.py:58-59` | `APPID` / `SECRET` 模块级常量 | 保留为「默认店铺回退」来源；正常路径从 `resolve(shop_id)` 的 `credentials` 取 |

```python
# 改造示意
_store_pool: dict[str, WxStore] = {}
_store_lock = threading.RLock()

def get_store(shop_id: str | None) -> WxStore:
    shop = shop_registry.resolve(shop_id, platform="wechat")
    with _store_lock:
        inst = _store_pool.get(shop["shop_id"])
        if inst is None:
            cred = shop["credentials"]
            inst = WxStore(cred["appid"], cred["secret"])
            _store_pool[shop["shop_id"]] = inst
        return inst
```

> **天然优势**：`WxStore` 的 token 缓存是**实例级**（`wechat/wechat_store_client.py:76-77` 的 `self._token` / `self._token_expire_at`），一店一实例即天然隔离，无需额外缓存分键。

### 4.1 数据库表结构改造（`bulk_api.py:102-145` 的 `db()`）

#### 4.1.1 加 `shop_id` 的 3 张表（可直接 `ALTER TABLE`）

#### 4.1.5 迁移函数 `_migrate_shops(conn)`（幂等）

调用位置：`db()` 内建表语句之后、`conn.commit()` 之前（约 144 行前）。

```
_migrate_shops(conn):
  1. 判断是否已迁移：PRAGMA table_info(batches) 是否含 shop_id → 含则直接 return（幂等）
  2. 备份：把 bulk_catalog.sqlite3 复制为 bulk_catalog.backup_<yyyyMMdd_HHmmss>.sqlite3

  3. 事务内：
```

## 7. 验收清单（逐项可勾选）

### 配置层
- [ ] 无 `shops.json` 时，三个服务启动后行为与改造前完全一致（单店回退）。
- [ ] `shops.json` 中 `shop_id` 重复、每平台多个 `is_default`、`enabled` 店铺缺凭证 → 启动即失败并给出明确错误。
- [ ] `GET /shops` 返回的清单**不含**任何密钥字段。

### 数据隔离
- [ ] `_migrate_shops` 重复执行两次结果一致（幂等），第二次不报错、不重复备份。
- [ ] 迁移前后各表 `COUNT(*)` 一致；`category_aliases` / `image_upload_cache` 行数与旧表相同。
- [ ] A 店导入的批次，用 A 的 `X-Shop-Id` 能读、用 B 的 `X-Shop-Id` 返回 404。
- [ ] 同一 `internal_category` 在 A、B 两店可各存一份别名，互不覆盖。
- [ ] 同一 `source_hash` 图片在 A、B 两店各自上传、各自缓存（不跨店复用 URL）。
- [ ] `/publish-status` 只返回当前店记录。
- [ ] `DELETE /image-cache` 只清当前店缓存。

### 微信 / 小红书
- [ ] 两店并发发品，`/products` 与 `/items` 列表互不串。
- [ ] `/token/test`、`/token/info` 返回的是请求店铺的凭证状态。
- [ ] 小红书 token 过期自动续期在 A 店触发时，**不会**影响/覆盖 B 店 token 文件。
- [ ] 类目树 / 运费模板 / 品牌列表按店分键，切换后立即可见变化。

### 发布链路
- [ ] Worker 线程名包含 `shop_id`；日志可区分店铺。
- [ ] 人为在 DB 里把某 item 的 `shop_id` 改成另一家，发布时被归属校验拦截并置失败（不串店）。
- [ ] 批量发布勾选两平台、两平台当前店铺不同时，各自发到正确的店。
- [ ] 失败清单可按店隔离查看与重试。

### 留痕
- [ ] 导入 / 发布 / 重试 / 改映射 / 切店 五类动作均写入 `operation_logs`。
- [ ] `batches.operator` / `publish_jobs.operator` 与请求头 `X-Operator` 一致。

### 前端
- [ ] 切店后商品列表、批次、映射、发布状态、当前任务全部刷新，无残留脏数据。
- [ ] 刷新浏览器后仍记住上次选择的店铺与操作人。
- [ ] 店铺管理页能展示各店 token 剩余有效期。
